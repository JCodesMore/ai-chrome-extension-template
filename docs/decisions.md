# Decision log

**Append-only.** Add a row when you make a decision that a future agent might otherwise
second-guess or silently reverse — especially the load-bearing product and architecture calls
for the extension you build (why this storage engine, why this ranking, why this API). Record
the date, the decision, and _why_ including the alternatives you rejected. Never rewrite or
delete rows; supersede a decision with a new row that references the old one.

## Template foundations

These are the template's own decisions — the ground your extension is built on. Don't undo them
without a strong, recorded reason.

| Date       | Decision                                                                                                                                                                       | Rationale & rejected alternatives                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-07-12 | **Chrome for Testing is the default dev browser** (auto-downloaded via `@puppeteer/browsers` into `.browser/`)                                                                 | Google removed `--load-extension` from _branded_ Chrome and Edge in v137 (May 2025), so detecting and driving an installed branded Chrome is **impossible** for this use case. Chrome for Testing is Google's officially recommended vehicle and still supports the flag. Rejected: requiring the user to supply a browser (fragile, and most installed browsers are branded) — `BROWSER_EXE` remains as an escape hatch for a local non-branded Chromium/Brave. |
| 2026-07-12 | **Zero-dependency CDP scripts as the harness** (raw CDP over the DevTools Protocol; `@puppeteer/browsers` is the _only_ tooling dependency, and only for fetching the browser) | Keeps `tools/` transparent, auditable, and cheap to modify by the agent — no framework abstraction between the agent and the browser. Rejected: Playwright/Puppeteer as the driver — heavier, more opaque, and their extension support is thinner than driving `chrome.developerPrivate` directly; a bug there is a black box, whereas a 30-line CDP script is not.                                                                                              |
| 2026-07-12 | **Extension reload via `chrome.developerPrivate`** (driven by evaluating on a `chrome://extensions` page target over CDP)                                                      | There is **no official CDP command** to reload an unpacked extension. `chrome.developerPrivate` is the same private API `chrome://extensions` itself uses, so it reliably reloads, reports manifest/runtime errors, and clears the sticky error log. Rejected: killing and relaunching the browser each edit (slow, loses state) and file-watch auto-reload (unreliable for MV3 service workers).                                                                |
| 2026-07-12 | **Single `public/manifest.json` with a dev-time rewrite**                                                                                                                      | One source of truth. Broad host access is declared as `optional_host_permissions` (lowest store-install friction); the dev build rewrites those to required `host_permissions` because native permission prompts can't be accepted over CDP, while `npm run package` ships the store variant unchanged. Rejected: two separate committed manifests (drift risk) and requiring permissions up front (higher install friction, worse store review).                |
| 2026-07-12 | **Agent-skill files are duplicated, not symlinked** (canonical `.claude/skills/…`; generated copies in `.agents/` and `.codex/` via `npm run sync`)                            | Symlinks are unreliable on Windows (require privilege/dev-mode, break across git checkouts and archive extraction). Duplication with a regenerate step is boringly portable. Rejected: symlinks (Windows breakage) and a single shared path (Codex and Claude look in different, fixed locations).                                                                                                                                                               |
